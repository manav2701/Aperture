# @aperture/db

Postgres schema, migrations, the budget ledger, and the audit chain.

## Schema (Drizzle, `src/schema.ts`)

`orgs`, `principals`, `budgets` (a tree; money or count units; hard or soft; per-rail), `budget_usage` (held/spent per budget per period), `holds`, `ledger_entries` (append-only journal), `audit_events` + `audit_org_counters` (hash chain). Business rules that can be constraints are constraints.

Migrations live in `migrations/`: `0000` is generated by drizzle-kit (`pnpm --filter @aperture/db db:generate` after schema changes); `0001` adds append-only triggers on the journal and audit log (they bind every role, including the owner) and the `aperture_app` role, which can't delete anything or modify history. Creating that role needs `CREATEROLE`.

## Ledger (`src/ledger.ts`)

| Function             | Purpose                                                                                                                                                                                                        |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reserve`            | Hold an estimated amount against the principal's budget path (its budgets, every ancestor, and an optional mandate budget). Fails closed without a budget or when the principal is paused. Idempotent per key. |
| `settle` / `release` | Convert a hold to spend in the periods it was reserved in, or give it back. Idempotent.                                                                                                                        |
| `expireHolds`        | Apply each expired hold's `onExpiry`: settle, release, or park as `expired_reconciling` (money stays held).                                                                                                    |
| `recordSpend`        | Spend that happened without a hold (card force captures, observed provider usage); reports hard budgets now over limit.                                                                                        |
| `refund` / `adjust`  | Credits (to the current period, never above the original) and signed corrections.                                                                                                                              |
| `verifyCounters`     | Recomputes counters from the journal (invariant I2).                                                                                                                                                           |

Every operation locks usage rows in ascending order inside one transaction — run one operation per transaction (ADR 0012). Time comes from the database clock.

## Audit (`src/audit.ts`)

`appendAuditEvent` (gapless per-org sequence under concurrency), `exportAuditEvents` (records for offline verification), `auditRoot`.

## Tests

Integration and property tests run against a real Postgres 17 started with Testcontainers (Docker required). A template database is migrated once; each test file clones it.

```bash
pnpm --filter @aperture/db test                                   # 30 tests
PROPERTY_RUNS=300 DEADLOCK_ROUNDS=150 pnpm --filter @aperture/db test   # what the nightly workflow runs
```

The concurrency suite checks INV-1…4 on random budget trees under concurrent reserve/settle/release/expiry, verifies exact approvals under 200-way contention on one budget, and hunts for deadlocks over crossing budget paths.
