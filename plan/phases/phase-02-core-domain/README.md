# Phase 2 — Core domain: money, ledger, budgets, policy, audit

**Goal:** build and prove the heart of Aperture — the pieces every rail relies on — as pure, heavily tested code before any UI or integration exists.
**Duration:** ~2.5 weeks.
**Depends on:** Phase 1.

## Starting point

Empty `packages/core`, `packages/db`, `packages/crypto` from Phase 1; Postgres in `compose.dev.yml`.

## Scope

**In:** money type; periods; price catalog types and cost estimation; database schema for budgets/ledger/holds/audit (and a minimal `orgs`/`principals`); ledger operations with row locking; policy engine v1; mandate data model + attenuation check (signing comes in Phase 7); audit hash chain + verifier; a CLI simulator.
**Out:** HTTP APIs, auth, UI, connectors.

## Tasks

### 2.1 Money (`packages/core/src/money`)
- `Micros` branded bigint; `parseUsd("12.345678")`, `formatUsd(micros, {decimals})`, `fromCents`, `fromAtomic(amount, decimals)` (USDC/USDT = 6 → identity), `mulRatioCeil(micros, num, den)` for prices.
- Reject: more than 6 decimals, negatives where not allowed, exponent notation, `NaN`, empty.

### 2.2 Periods (`packages/core/src/period`)
- `periodKey(instant, period, timezone)` → `"2026-09-23"`, `"2026-W39"`, `"2026-09"`, `"H2026-09-23T14"` (hour windows for count budgets), `"all"`.
- `periodBounds(key, timezone)` → `[start, end)`.
- Use `@js-temporal/polyfill` (or `date-fns-tz`) — decide in an ADR; no hand-rolled timezone math.

### 2.3 Pricing and estimation (`packages/core/src/pricing`)
- Types: `PriceEntry { provider, model, inputPerMTok, outputPerMTok, cacheReadPerMTok?, cacheWritePerMTok?, perImage?, perSecond?, effectiveFrom }` in µUSD.
- `estimateTextCost({bytes, images, maxOutputTokens}, price)` using `ceil(bytes/3)` input tokens; `actualTextCost(usage, price)`; `estimateMediaCost({seconds, count, resolution}, price)`. All `ceil`, minimum 1 µUSD.

### 2.4 Database schema v1 (`packages/db`)
- Drizzle tables from [architecture §5](../../architecture/README.md#5-domain-model): `orgs` (minimal), `principals` (minimal), `budgets`, `budget_usage`, `holds`, `ledger_entries`, `audit_events`, `audit_org_counters`.
- Migrations generated by drizzle-kit and committed; a migration test applies them to an empty DB.
- DB roles created in a migration: `aperture_app` (no UPDATE/DELETE on `audit_events`, `ledger_entries`), `aperture_migrator`. Trigger that raises on UPDATE/DELETE of `audit_events` and `ledger_entries`.

### 2.5 Ledger operations (`packages/db/src/ledger`)
- `reserve`, `settle`, `release`, `recordUnheld`, `refund`, `adjust`, `expireHolds` exactly as specified in [architecture §7](../../architecture/README.md#7-ledger-and-holds), each taking a `tx`.
- `resolveBudgetPath(principalId, rail, mandateId?)` — principal budgets + ancestors + mandate budget, filtered by rails.
- Lock order: ascending `budget_id`; `INSERT … ON CONFLICT DO NOTHING` for missing usage rows before locking.
- Return typed results: `{ ok: true, hold }` or `{ ok: false, reason: 'budget_exceeded', budgetId, remaining }`.
- `verifyCounters(orgId)` recomputes `budget_usage` from `ledger_entries` (used by the nightly job later).

### 2.6 Policy engine (`packages/core/src/policy`)
- Zod schemas for each rule type in [architecture §9](../../architecture/README.md#9-policy-engine); `PolicyDocument = { rules: Rule[] }`.
- `evaluate(input): Decision` — pure, total (never throws; internal errors → `deny` with `policy_error`).
- Model pattern matcher (exact or trailing `*`), time-window evaluation in org timezone, merchant/country/payee matching.
- Obligation merging (min `maxTokens`, strictest logging).

### 2.7 Mandate model (`packages/core/src/mandate`)
- `MandateScope` Zod schema; `isWithin(child, parent): { ok } | { ok: false, violations[] }` covering rails, providers, model patterns, payees, per-action cap, budget, validity window, uses.

### 2.8 Audit chain (`packages/crypto` + `packages/db/src/audit`)
- RFC 8785 JCS canonicalization (use a maintained library, e.g. `canonicalize`), SHA-256.
- `appendAuditEvent(tx, orgId, event)` — locks the org counter row, computes `seq`, `prev_hash`, `hash`.
- `verifyChain(events)` and `merkleRoot(hashes)`; `tools/audit-verify` CLI reading JSONL.

### 2.9 Simulator (`tools/try/simulate.ts`)
- Reads a YAML scenario (org, budget tree, policies, a list of actions with timestamps and concurrency) and prints each decision, holds, and remaining budgets. Used for demos and to explore edge cases quickly.

## Edge cases covered

L1–L9, L15, L16, P1, P3, P8, P9, O5 (see [edge-cases](../../edge-cases/README.md)).

## Tests

**Unit (Vitest):** money parse/format tables; period keys for boundary instants (month end, year end, ISO week 53, Asia/Dubai, America/New_York DST days); cost estimation examples per provider; each rule type allow/deny cases; `isWithin` violation messages; JCS vectors from RFC 8785.

**Property (fast-check):**
- INV-1 hard budget never exceeded — random trees (depth ≤ 5, 1–20 nodes), random op sequences (reserve/settle ≤ hold/release/expire), executed with **real concurrency** (1–64 connections) on Testcontainers Postgres.
- INV-2 counters = journal fold; INV-3 terminal states; INV-4 idempotency with duplicated ops.
- INV-5 money round-trip; INV-6 period partitioning across random instants and timezones.
- INV-7 policy monotonicity; INV-8 scope intersection; INV-15 audit tamper detection.

**Fuzz:** INV-10 `evaluate(fc.anything())` never allows and never throws; `parseUsd(fc.string())` never throws unexpectedly; policy document schema with arbitrary JSON.

**Integration:** deadlock hunt (L2) — 10k randomized reserve/settle interleavings across overlapping budget paths, assert zero `deadlock_detected` errors; trigger test that UPDATE/DELETE on `audit_events` fail for `aperture_app`.

**Performance smoke:** 200 concurrent reserves on one budget complete with p99 < 15 ms on the dev machine (record the number; it becomes a regression guard).

## Security checklist

- [ ] App DB role can't modify `audit_events` / `ledger_entries` (test)
- [ ] No `number` arithmetic in money code (lint + review)
- [ ] Policy engine fails closed on invalid input (INV-10)

## Deployment

None (library phase). CI runs the full property suite with bounded runs; a nightly workflow runs 100× more cases.

## Try it yourself

```bash
pnpm --filter @aperture/core test          # unit + property tests
pnpm --filter @aperture/db test:integration  # concurrency tests on real Postgres
pnpm try:simulate plan-examples/two-teams.yaml
```
Example scenario to run: Org USD 100/month → Marketing USD 60 → Agent A USD 50/day; fire 20 concurrent USD 5 requests from Agent A → exactly 10 approved (the day budget), the rest `budget_exceeded` naming Agent A's budget. Then lower Marketing to USD 30 → next request denied naming Marketing. Then tamper one audit line in the exported JSONL and run `pnpm audit-verify` → it reports the first broken `seq`.

## Exit criteria

- [ ] All invariants INV-1…8, 10, 15 pass with ≥ 10,000 generated cases each in the nightly run
- [ ] `packages/core` coverage ≥ 95%
- [ ] Reserve p99 benchmark recorded
- [ ] Simulator runs the example scenarios
- [ ] ADR for the date/time library written

## Risks / open questions

- If single-budget contention is a bottleneck later, the design allows moving hot counters to Redis with Postgres as the journal — only after INV-1 is re-proven for that design.
